# Материалы для Codex: TSPU-устойчивость, модульная сборка, Teleport

Этот каталог создан независимой технической экспертизой от 2026-11-21 для ревизии `850ce47fb2d224fc49630b5878107150c1b711e0` (ветка `codex/rp-24x7-lab`, версия `1.2.9-lab.18`).

**Каталог ничего не меняет в работающей системе.** Он добавлен отдельной веткой `docs/codex-guidance`. Файлы `rp.sh`, `src/`, `tests/`, `lab/`, `reports/` и ветка `main` не затронуты. Содержимое нужно перенести в рабочую ветку только решением владельца проекта.

## Главный приоритет проекта

Смысл `rp` — туннели между VPS-1 (Россия) и VPS-2 (за границей), которые **как можно дольше остаются работоспособными под давлением ТСПУ**. Транзакционный откат, самообновление и аккуратная установка важны, но вторичны: они защищают установку, а не доступ к VPS-2.

Из этого следует порядок работ, отличный от первоначального плана в экспертизе:

1. Сначала **измерить** устойчивость четырёх транспортов к моделируемому давлению (задание T1). Код `rp.sh` при этом не меняется.
2. Затем, если измерения покажут слабые места, **усилить транспорты** отдельным заданием и выпустить `rc.2` (задание T2).
3. Только после этого начинать рефакторинг (T3–T5) и Teleport (T6–T7). Менять поведение транспортов одновременно с переносом кода нельзя: побайтное сравнение с эталоном перестаёт работать.

## Как пользоваться

1. Владелец читает `INVARIANTS.md`, правит и подтверждает. Без этого ни одно задание не начинается.
2. Задания выдаются **по одному**, строго по порядку из `tasks/`. Каждое начинается от тега `task-N-accepted` предыдущего (для T0 — от `850ce47` или от тега rc.1).
3. После каждого задания владелец читает записку `reports/TASK-N.md`, раздел «Не проверено», и сам (или отдельной сессией-ревьюером) запускает ворота.
4. Если Codex остановился по условию остановки из `AGENTS.md`, это штатный исход: ответ записывается в `DECISIONS.md`, задание перезапускается с того же тега.

## Границы достоверности

- **Проверено мной при составлении:** состав репозитория, запуск 155 тестов (все проходят), статический анализ, строки кода, на которые даны ссылки, содержимое `deploy-teleport.sh`.
- **Не проверено:** любые стендовые результаты (Rocky 10.2, перезагрузки, T1–T3), поведение на реальных каналах РФ, подлинность RPM Teleport, поведение Teleport 18.x на Rocky 10 (команды в `TECHNICAL-DETAILS.md` помечены «проверить по документации»).
- **О ТСПУ:** раздел `TSPU-RESISTANCE.md` опирается на открытые обсуждения и одну научную работу. Многие утверждения в источниках спорные и не подтверждены производителями; в тексте они отмечены. Это гипотезы для проверки на вашем канале, а не знание о том, как устроен ТСПУ.
