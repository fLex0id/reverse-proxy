# T0. Подготовка репозитория и условия rc.1

**Тип:** документы, CI, небольшие правки установки. Транспорты не менять.
**База:** `850ce47fb2d224fc49630b5878107150c1b711e0` (или более поздний коммит ветки `codex/rp-24x7-lab`, если владелец подтвердил). Новая ветка `task/0-prepare`.
**Читать:** `AGENTS.md`, `INVARIANTS.md` (подтверждён владельцем), `DECISIONS-seed.md`, `AUDIT-SUMMARY.md`, `reports/STATUS.md`.

## Цель

Сделать так, чтобы дальнейшие задания не теряли прогресс, и закрыть условия rc.1, которые не требуют стенда.

## Часть A. Документы и защиты (без правок `rp.sh`)

1. Скопировать содержимое `docs/codex-guidance/` в `docs/` рабочей ветки; `AGENTS.md` — в корень. Документы без изменений, кроме подтверждённого владельцем `INVARIANTS.md`.
2. Создать `docs/DECISIONS.md` из `DECISIONS-seed.md`. Колонку «Тест» заполнить **по коду**: найти реальный тест, защищающий каждое решение (`файл::имя`). Если теста нет, написать `NO_TEST` и вынести в «Открытые вопросы».
3. Заполнить `docs/DEFECT-TEST-MAP.md` так же (по каждому RP-…).
4. В `reports/ACCEPTANCE.json` добавить поле `title` для каждой строки F01–F13: короткое название, понятное без внешнего документа. Статусы **не менять**.
5. Добавить в CI проверки из `AGENTS.md`: число тестов не меньше 155; запрет на удаление `assert` и добавление `skip`/`xfail` в `tests/` без пометки; `static-check.py`.
6. Удалить `rp_gpt.sh` из корня (старая сборка со своим `RP_URL`). Перед удалением сохранить ссылку на коммит в записке.
7. Создать `docs/KNOWN-LIMITATIONS.md` для rc.1. Включить только то, что подтверждено отчётами: Rocky 9 не проверялся; шестичасового прогона нет; сценарии давления (заморозка/сброс потока, лимит соединений, блокировка QUIC) не испытывались (до T1); Google STUN; нативный IPv6; перечень строк `ACCEPTANCE.json` со статусами `NOT_TESTED`/`UNKNOWN`. Ничего не приукрашивать.

**Ворота части A:** тесты 155+ проходят; `static-check.py` проходит; `git diff 850ce47 --stat` не затрагивает `rp.sh`, `src/`, `tests/` (кроме CI-проверки), `lab/`.

## Часть B. Канал обновления (правки `rp.sh`; отдельные коммиты)

Подробности и аргументы: `TECHNICAL-DETAILS.md` §6. Делать только после ворот части A и согласия владельца на детали подписи (§6.2, п. 2: формат ключа и порядок подписи — решает владелец; Codex ключ не хранит).

1. **Запрет понижения.** Ввести `schema_version`; запуск более старой версии поверх более новой схемы — отказ без явного `--allow-downgrade`; без терминала ответ по умолчанию «нет». Тест на оба режима.
2. **Проверка подлинности.** Заменить проверку «только формы» (`self_ok`) проверкой `SHA256SUMS` и подписи; открытый ключ встраивается в сборку. *Проверить* поддержку Ed25519 с `-rawin` в OpenSSL Rocky 9 и 10 до реализации; если не поддерживается — остановиться и описать альтернативу.
3. **`RP_URL`.** По умолчанию — неизменяемый тег релиза, не `main`. Переменную переопределения оставить.
4. Существующее поведение отката самообновления (D5, D6, D12) **не менять**.

**Ворота части B:** все прежние тесты проходят без правок ожиданий; новые тесты на отказ при подделанном файле, при несовпавшем хэше, при понижении; ручная проверка на стенде — запись `NOT_RUN`, если стенда нет.

## Нельзя

Менять параметры транспортов, тайминги сторожа, форматы данных. Вырезать или переименовывать функции. Трогать `main`.
