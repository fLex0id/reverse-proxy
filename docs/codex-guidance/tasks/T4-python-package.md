# T4. Python-пакет `rp` и единый движок транзакций

**Тип:** рефакторинг с сохранением формата снимка.
**База:** тег `task-3-accepted`. Ветка `task/4-python-package`.
**Читать:** `AGENTS.md`, `TECHNICAL-DETAILS.md` §3.2, §5, `DECISIONS.md` (D5, D6, D12).

## Цель

Вынести Python в настоящий пакет и устранить дублирование двух движков транзакций, ничего не меняя в наблюдаемом поведении и формате снимка.

## Сделать

1. **Сначала письменно сравнить** десять одноимённых функций двух движков (`arm`, `atomic`, `command`, `digest`, `disarm`, `load`, `main`, `rollback`, `save`, `valid_member`). Для каждой: идентична / различается и почему. Различия — в `DECISIONS.md`, **не исправлять молча**.
2. Вынести `rp.py` в `src/python/rp/` (`gen.py`, `__main__.py`), движки — в `txn.py`, снятие манифеста — в `state.py`.
3. Объединить движки в `rp/txn.py` с параметризацией по роли. Формат снимка и порядок операций не менять. Добавить в снимок поле `schema_version` (только поле; логику чтения расширить без изменения существующих снимков).
4. Установка распаковывает пакет в `/usr/local/lib/rp/py/rp/`; запуск `python3 -I -B -m rp …` либо эквивалент, проходящий на Python 3.9 (Rocky 9) и новее. Если `-I` мешает `-m`, выбрать запасной вариант и записать решение.
5. Вынести `capture_runtime` в команду `rp state-manifest`.
6. Перевести тесты, режущие `rp.sh` по маркерам, на импорт модулей. Утверждения не менять.

## Ворота

- Все золотые файлы без изменений; тест CLI проходит; 155+ тестов, число не уменьшилось.
- Тесты `test_transaction.py`, `test_migration.py`, `test_migrate_failures.py`, `test_update_lock.py` проходят **без правок ожиданий**.
- **Манифест состояния** (§4.3): на одном откатанном снимке установить эталон и новую сборку, снять `rp state-manifest`, сравнить. Допустимое различие — версия. Если стенда нет, `NOT_RUN` и что нужно владельцу.
- T1–T3 четырёх транспортов — один проход на стенде (или `NOT_RUN`).

## Нельзя

Менять формат снимка или алгоритм отката (стабильный версионированный формат — предмет отдельного решения, §5.3). Добавлять зависимости. Менять тайминги.
