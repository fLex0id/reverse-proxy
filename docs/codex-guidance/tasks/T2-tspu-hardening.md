# T2. Усиление транспортов (условное; запускать только по решению владельца)

**Тип:** изменения поведения транспортов. **Единственное задание, где это разрешено.**
**База:** тег `task-1-accepted`. Ветка `task/2-tspu-hardening`. Результат — кандидат `v1.2.9-rc.2`.
**Читать:** `AGENTS.md`, `INVARIANTS.md`, `TSPU-RESISTANCE.md`, `reports/results/tspu/SUMMARY.md`.

## Условие запуска

Задание выдаётся **только** если в `SUMMARY.md` есть конкретные неудачи, и **только** по тем неудачам, которые там показаны. Владелец вписывает в начало файла выбранный список изменений. Всё, что не вытекает из измерений, — в «Предложения».

## Возможные изменения (кандидаты, не обязательства)

Каждое включается только при подтверждающем измерении из T1, отдельным коммитом, с тестом и записью в `DECISIONS.md`.

| Кандидат | Когда включать | Заметки |
| --- | --- | --- |
| **Обнаружение остановки потока** по счётчикам внутреннего WG (отправка растёт, приём нет) и по давности рукопожатия; переключение без ожидания трёх проб | T1 показал, что замораживание (S-FREEZE/S-RST) обнаруживается дольше 60 с | Проверить, нет ли уже; не ломать защищённое поведение RP-006 (D10) |
| **Расширенная проба объёма**: помимо 200 КиБ, периодическая проба больших объёмов (например 1 МиБ) с контролем прогресса | T1 показал отсечки при объёмах больше 200 КиБ | Пробы не должны создавать всплесков соединений (H2) |
| **Бюджет соединений и «вежливое» переподключение**: потолок новых рукопожатий за окно, экспоненциальная пауза с джиттером, без серий быстрых попыток | T1 показал всплески при переключении/пробах, либо реальный канал реагирует на частоту (H2) | Не противоречить цели 60 с; согласовать цифры с владельцем |
| **Параметры XHTTP** (`maxConcurrency`, `xmux`, режим) | T1 показал связь числа соединений с отказом | Текущие значения — `rp.sh:5877–5883` |
| **Отпечаток ClientHello**: опция `RL_FP` с A/B-проверкой значений | T1/H3 показали разницу на реальном канале | Значение по умолчанию менять только по данным реального канала владельца |
| **Порядок транспортов по умолчанию** | T1 показал, что один класс (например UDP) ненадёжен на эталонных каналах | Решение владельца |
| **Диагностика отказа**: `rp diag` явно называет вероятный класс (заморозка, сброс, нет UDP, нет ответа) | Всегда полезно, но не обязательно | Только чтение, без изменения поведения |

## Ворота

- Для каждого изменения: повтор **той же** матрицы T1 на новой сборке; улучшение по метрике, из-за которой изменение внесено; отсутствие ухудшения по остальным.
- Полная регрессия четырёх транспортов (`lab/full_transport_regression.py`) и все 155+ тестов проходят.
- Захват на подложке: прямого выхода нет (I2).
- Результаты, включая неудачи и ухудшения, — в `reports/results/tspu/`.

## Нельзя

Менять больше, чем подтверждено измерениями. Заявлять устойчивость к реальному ТСПУ. Менять формат данных и имена команд. Смешивать с T3–T5.
