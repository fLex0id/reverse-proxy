# T7. Модуль Teleport

**Тип:** новая функциональность в изолированном модуле.
**База:** тег `task-5-accepted` **и** утверждённый `docs/TELEPORT-DESIGN.md` (T6). Ветка `task/7-teleport-module`.
**Читать:** `AGENTS.md`, `INVARIANTS.md` (I6, I7), `TECHNICAL-DETAILS.md` §8–§9, `docs/TELEPORT-DESIGN.md`.

## Цель

Реализовать `src/bash/integrations/teleport.sh` и `teleport.meta` строго по утверждённому проекту. Основа — идеи `deploy-teleport.sh`, но **не** как второй параллельно сопровождаемый установщик: исходный скрипт остаётся нетронутым, пока владелец не решит иначе.

## Сделать

1. Модуль и `teleport.meta` (версия, URL пакетов, SHA256; версия обновляется только через метаданные).
2. Точка вызова из `rp`: предложение **после** успешной установки и базовой проверки; по умолчанию «нет»; повторный запуск не предлагает снова без явной команды.
3. Обнаружение существующей установки; в случае наличия — статус и только `join-only` (если это разрешено проектом).
4. Установка пакета (`rpm`/`dpkg`) с проверкой двух хэшей; расхождение останавливает установку; Teleport не обновляется через `dnf`.
5. Конфигурация по проекту; порт не 443/8443; записи брандмауэра помечены.
6. Регистрация VPS-2: токен на 10–15 минут, передаётся по `rp push`, хранится только в `/run` (`0600`), удаляется после вступления узла; проверка по `tctl nodes ls`.
7. Тесты по плану проекта. Тест независимости (I7): между юнитами нет `Requires/BindsTo/PartOf`; откат и удаление `rp` не меняют `/etc/teleport*`, `/var/lib/teleport`, бинарники Teleport; Teleport не меняет правила и зоны `rp`.

## Ворота

- **Хэши модулей ядра** (`core`, `system`, `net`, `roles-*`, `txn`, `cli`) не изменились относительно `task-5-accepted` (`build/MODULES.sha256`). Если изменились — остановиться: приёмка ядра больше не действительна.
- Тесты Teleport и невмешательства проходят.
- На стенде: чистая установка; установка рядом с существующим кластером без перезаписи; регистрация VPS-2; повторный захват на подложке — прямого выхода нет.
- Если стенда нет — `NOT_RUN` с описанием.

## Нельзя

Менять ядро. Включать установку по умолчанию. Дублировать управление Teleport в меню `rp`. Менять DNS или время системы. Хранить токен на диске дольше регистрации.

## После

Приёмка финальной сборки (владелец): полная регрессия, шестичасовой прогон на неизменной сборке, проверки обновления и удаления.
