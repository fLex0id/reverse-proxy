# Restart behavior under actual service failures

Baseline lab.11; candidate lab.12; existing Rocky 10.2 endpoints and isolated
Debian WG client. Candidate scripts were uploaded and executed without first
replacing the installed baseline. Private runtime drop-ins affect only the named
rp/WG service; independent 180-second timers remove them and restore services.

## VPS-1

Stop `wg-quick@wg0` and `rp-echo`, then invoke baseline `rp restart`. It returns
zero and prints success, but both services remain inactive; client HTTPS times
out (curl 28). Candidate restart explicitly includes these services, applies the
existing systemd network ordering, and verifies local service/listener/routing
readiness. Both services become active and client HTTPS succeeds.

Next, override only the runtime wg0 ExecStart with `/usr/bin/false`. Candidate
restart returns one. systemd reports `ExecMainStatus=1`, `ActiveState=failed`.
The exact drop-in is removed, services and client restored, timer disarmed and
private fixture removed. This verifies an actual service failure, not only a
mocked `systemctl` exit code.

## VPS-2

The active packet-up Xray service receives a private runtime ExecStart failure
with automatic restart disabled for that fixture. Watch supervision is paused
under an independent restoration timer. Baseline `rp restart` returns zero while
the unit is failed. Merely checking `systemctl start` status was insufficient in
the first candidate: Type=simple startup can succeed before the process exits.
That failed candidate test is retained in `restart2-fault-lab12`.

The final candidate also checks failed-unit state and uses bounded functional
reverse-tunnel probes. It returns one for the same actual failure; both runs
show `ExecMainStatus=1`, `ActiveState=failed`. After restoration, the reverse
functional probe, watcher and client HTTPS pass. Full update/selection T1–T3
requirements were unchanged; restart readiness is a separate bounded check.

## Scope

124 local tests and generated-code static checks pass. Private artifacts:
`restart-fault-lab12`, `restart-fault-lab12-repeat`,
`restart2-fault-lab12`, `restart2-fault-lab12-repeat`.

Client availability is not instantaneous: the VPS-1 fixture recorded a failed
initial client probe during restoration and subsequent success. Raw operations
and curl statuses are retained. These observations do not prove zero downtime,
the complete failover SLA or packet-level leak absence during every restart.
Broader transport regression and final clean acceptance remain separate work.
