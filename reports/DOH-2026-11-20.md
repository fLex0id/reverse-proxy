# Quad9 path comparison and kernel-reset leak

Existing installation: rp lab.4 (`61dbdf5`); strict probe functions from lab.5
(`65b3fed`) sourced without installing that candidate. HY2 + Salamander pinned;
automatic selection restored afterwards. All captures and detailed probe errors
remain private under `lab/artifacts/doh-path-20261120`.

The operator confirms that the lab hosts and controller themselves reach the
internet through VPN and an environment subject to TSPU filtering. A failing
external endpoint is not automatically an rp defect. Keep the failure visible,
compare the same numeric destination independently, classify uncertainty and
continue other acceptance work; do not weaken checks or loop indefinitely.

## Paired measurements

Ten repetitions of six endpoints, two simultaneous paths per endpoint: LAB-1
SOCKS through rp versus direct LAB-2 curl with proxies explicitly disabled.
Each request validates TLS normally and validates the complete HTTP/DNS answer.
The named variants retain TLS hostname verification and SNI but pin their network
destination with `--connect-to`; local/system DNS cannot change the destination.

| Endpoint variant | Through rp | Direct LAB-2 |
|---|---:|---:|
| Quad9 9.9.9.9, IP URL | 9/10 PASS | 6/10 PASS |
| Quad9 9.9.9.9, dns.quad9.net URL | 8/10 PASS | 7/10 PASS |
| Quad9 149.112.112.112, IP URL | 6/10 PASS | 9/10 PASS |
| Quad9 149.112.112.112, dns.quad9.net URL | 10/10 PASS | 8/10 PASS |
| Cloudflare 1.1.1.1, IP URL | 10/10 PASS | 10/10 PASS |
| Cloudflare 1.1.1.1, cloudflare-dns.com URL | 10/10 PASS | 10/10 PASS |

Totals: 103/120 PASS, 17 FAIL. All failures are curl 35 during TLS connection,
before an HTTP/DNS response: seven proxied and ten direct failures. Direct errors
report connection reset by peer; proxied errors report TLS connect failure.
LAB-2 capture confirms incoming TCP resets with Quad9 source addresses. It cannot
identify whether the remote service, VPN gateway or an intermediate device
generated them. Named/SNI variants also fail, so absence of SNI alone is not a
sufficient explanation. Both IP-based and named endpoints are documented by
[Quad9's Cloudflared guide](https://docs.quad9.net/Setup_Guides/Miscellaneous/Cloudflared_and_Quad9/)
and [service directory](https://docs.quad9.net/services/).

RP-005 classification: **ENVIRONMENT_DEPENDENT / external cause probable**.
The failure is independently reproducible without the rp forwarding path; it
does not establish an rp-specific TLS defect. No guarantee about all environments
or the exact origin of resets is claimed. Keep these FAIL results, retain the
configured resolvers and continue qualification; no retry masking or silent
resolver replacement was added.

## Separate local defect RP-015

LAB-1 capture contains 18 TCP RST packets on its underlay, source 10.77.0.1,
destination Quad9. No DNS payload was present, but the exposed metadata and direct
egress violate the intended inner-WG path. This is independently reproducible
inside the lab with one ACK to a closed socket, without any public endpoint.

| Local reset fixture | ACK arrives on WG | RST on LAB-1 underlay | RST on WG | Guard drops |
|---|---:|---:|---:|---:|
| Installed lab.4 | yes | 1 | 0 | guard absent |
| Installed lab.6 | yes | 0 | 1 | 0 |
| Lab.6, source rule deliberately removed | yes | 0 | 0 | 1 |

Lab.6 adds source routing into the existing table 200 (including its prohibit
default) and an independent output guard. Missing-rule test had a 90-second
independent restoration timer; the rule was restored and the timer stopped.
Artifacts: `rst-before-20261120-b`, `rst-after-20261120`, `rst-guard-20261120`.
An initial fixture attempt used an unsupported PCAP link identifier; it is
retained as a harness error, not counted as a product result.

These are scoped tests. Complete four-transport and fault regressions remain
required before final acceptance; the six-hour soak has not started.
