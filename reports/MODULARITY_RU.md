## Сравнение с lab.23

`tools/compare-functions.sh --dist DIR` проверяет объявления через
`declare -f`, в том числе терминальную функцию оформления, и извлекаемый
Python. В модульном пакете найдены все **196** функций. У **186** тел
совпадение полное, у **10** есть перечисленные ниже различия. В резервном
монолите совпадают **189**, отличаются **7**. Все **11** фрагментов Python
совпадают побайтно, включая генератор и оба транзакционных помощника.
Сгенерированное дерево и права файлов VPS-2 совпадают. Для сравнения полного
установщика с фиксированным вложением нормализуется только номер выпуска в
заголовке VPS-1.

| Функции | Причина отличия |
| --- | --- |
| `migration_source`, `py_source`, `transaction_source` | Модульный вариант читает тот же Python из локального файла. Монолит сохраняет heredoc. |
| `self_ok`, `self_explain_invalid` | Проверка формата загрузчика и диспетчера, сохранён прежний контроль монолита. |
| `self_source`, `maybe_save_launched_build` | При запуске через модуль используют путь к исходному диспетчеру. |
| `self_install`, `self_upgrade` | Публикация локального дерева, установка диспетчера и переход через проверенный загрузчик. |
| `cmd_uninstall` | Перед очисткой модулей сохраняет рабочую команду rp в виде монолита, совместимо со старой семантикой удаления. |

Новые функции пакета: `rp_distribution_kind`, `rp_publish_modules`,
`rp_restore_single`. Изменения в сетевых функциях отсутствуют по сравнению
объявлений. Это доказательство переноса исходников, сетевые проверки ниже
отдельно оценивают работу установленного кандидата.

## Дефекты и наблюдения

- В начальном `lab.24` SELinux на Rocky присвоил каталогу модулей
  `user_tmp_t` вместо `lib_t`. Код публикации `lab.25` исключает копирование
  временных xattrs и восстанавливает метки до активации.
- В первом CI Python на Rocky и Ubuntu использовал разные zlib. GNU gzip
  обеспечил совпадение сборки до завершения статической стадии Ubuntu.
  Тесты, выполняющие chown и реальные проверки UID, запускаются в CI с root.
- На чистом VPS-2 с `lab.24` три транспорта прошли первичные T1–T3.
  Stream-up прошёл T1 и получил ошибку T2. Обе выбранные цели SNI прошли
  отдельные проверки TLS 1.3, h2 и X25519. Причина отказа T2 не установлена.
- С VPS-1 открылся TCP/22 на LAN-интерфейсе VPS-2. В исходной настройке зона
  `public` разрешает `ssh`. Вход по `rp ssh` через packet-up тоже проверен
  со сверкой отпечатка VPS-2. Для публичного Интернета лабораторного
  измерения пока нет.

## Не удалось проверить и остаточные риски

- Полный стендовый блок lab.25 ожидает подтверждения снимков всех трёх VM.
  Для изменения исходного доступа к TCP/22 на VPS-2 требуется решение
  владельца. Разрешения на изменение этого правила пока нет.
- Две серверные VM находятся в общей LAN. Публичные ограничения VPS-2,
  отличный выходной IPv4 в реальной двухсетевой схеме, OpenWrt, Rocky 9
  и устойчивость к реальному ТСПУ не были проверены.
- Исходный отказ stream-up оставлен как FAIL. Повторяемость на lab.23 и lab.25
  и причина отказа ещё не установлены.
- Частные стендовые логи лежат в `/tmp/rp-modular-lab` на управляющей
  машине. Файлы с ключами и исходные данные клиента исключены из Git.
